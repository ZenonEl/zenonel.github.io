Get the data and print it

I needed to get the band's data, which the Gadgetbridge app already keeps in its database, and print it for analysis. Band apps smooth their charts and hide short spikes, while anyone reading the data needs hours, minimums, and what was happening at that moment.

I built it by hand with the Gemini web chat. The first version appeared on 25 February 2026, the reports on 28 February and the diary bot on 1 March; all of it took five days.

What it builds

The script reads samples from the Gadgetbridge table with plain SQL and builds a report for the chosen period: trend charts at four days per page and an hourly table of minimum, mean and maximum. There is also a monthly summary with the average heart rate during sleep hours, 22:00 to 06:00.

A Telegram bot keeps a symptom diary, and its entries go straight into the PDF next to the charts, so you can see what was happening when the heart rate jumped. All of it is 519 lines of Python.

Not a medical device

The README says plainly that this is not a medical device and replaces no examination. The report helps prepare the data for a conversation with whoever reads it, but it makes no diagnosis.

Where it stands

The project is done for its task and works. The last change was on 4 May 2026: the Docker build was aligned with the uv lockfile. There are no tests, and the data is read only from the Gadgetbridge database and for one type of band.

How it is built

Architecture
  • SQL queries against the Gadgetbridge database, processing in pandas, charts in matplotlib, a PDF build.
  • An aiogram diary bot writes entries that end up in the report.
Infrastructure
  • Python with uv, run in Docker.
Data and AI
  • The data stays on your own machine: the Gadgetbridge database is read locally.
  • Not a medical device, no diagnoses.
