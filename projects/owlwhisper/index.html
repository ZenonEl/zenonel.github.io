A messenger without a server

I wanted to see how far a messenger with no central server could go: nodes find each other and talk directly. I built it by hand with the Gemini web chat, on my own.

I made the first commit on 19 August 2025, the first network, protocol and storage layers appeared on 20 August, and reaching a working MVP took about six weeks, to the end of September: a Fyne interface arrived on 7 September, followed by work on the core and the interface. August and September 2025 brought 99 commits and about 5,000 lines of Go.

How it works

Two instances on a network find each other through libp2p and a Kademlia DHT and talk over my own protocol of eight protobuf modules. One-to-one chats are encrypted with standard primitives, X25519, HKDF and AES-256-GCM, with no home-made cryptography. Files go in chunks, and calls run over WebRTC with Opus.

The layers are separate: the network, services with the logic, and the interface, which talks to the core only through interfaces and receives events from a typed channel, so the network never blocks the window.

Why I stopped

Past that point two problems of a different size were waiting: group end-to-end encryption at the level of Signal or MLS, and hiding who talks to whom from someone who can watch the traffic. I tried running libp2p over Tor and dropped it: it was complex, too slow for calls, and still left traffic correlation open.

I decided against shipping a messenger that only looks safe and halted the project in September 2025.

Where it stands

In 2026 I wrote a review of my own code into the repository: there are no tests, there is no forward secrecy because one key covers a whole session, the quic-go dependency panics after about a minute, part of the code sits outside Go conventions, and one mutex guards too much. If I come back to it, I start with tests, the Noise protocol for the handshake and MLS for groups.

How it is built

Architecture
  • Networking on libp2p and a Kademlia DHT, my own protocol of eight protobuf modules.
  • Layers for network, services and interface; the core is reachable only through interfaces, and events flow through a typed channel.
Infrastructure
  • Go, a Fyne interface, calls through pion/webrtc and Opus.
Data and AI
  • One-to-one encryption on X25519, HKDF and AES-256-GCM.
  • No forward secrecy and no group encryption, which is why it was not released.
Decisions and assumptions
  • Standard cryptographic primitives instead of my own.
  • Halt the project rather than ship an unsafe one.
