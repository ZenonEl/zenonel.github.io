A phone instead of a gamepad

Sometimes a controller will not connect to the computer directly: no drivers, Bluetooth pairing fails, but the phone can see it. Sometimes there is no physical gamepad at all. In both cases the phone can become the gamepad.

I made the first commit on 11 September 2024, and on 14 September a stable v0.1.0 on pyxinput came out. I started by hand with the Gemini web chat.

How it works

The phone opens a page, the browser reads input through the Web Gamepad API or on-screen buttons and sends it over a WebSocket to a FastAPI server. The server writes real evdev events into /dev/uinput, and the system sees an ordinary Xbox 360 pad, so the game needs no configuration.

On startup the server prints a QR code with the local network address to the console: point the camera and the interface opens. If an external tunnel address is set, a second QR code is printed next to it, and the gamepad works away from home too.

Three rewrites of one bridge

The project went from pyxinput and a Flask web interface in September 2024 to FastAPI in August 2025. On 6 March 2026 it moved to uv and Python 3.13, and on 11 May, with Claude, the X and Y button mapping was fixed and both READMEs were rewritten.

Where it stands

I have played many different games through it, and the system saw the phone as an ordinary gamepad. The project is small: 49 commits, no tests, Linux only.

How it is built

Architecture
  • The phone's browser, a WebSocket, a FastAPI server, evdev events into /dev/uinput.
  • The virtual device presents itself as an Xbox 360 gamepad.
Infrastructure
  • Python 3.13 with uv, an HTMX interface, QR codes in the console.
  • The external address is set by an environment variable for any tunnel.
Decisions and assumptions
  • A system gamepad instead of per-game settings.
  • Connecting by QR code instead of typing an address.
