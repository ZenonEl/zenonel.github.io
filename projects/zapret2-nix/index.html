zapret2-nix

A declarative NixOS module and preset library for zapret2: a service on nftables or iptables, with the strategy switchable on a running machine without a rebuild.

Why a module

nixpkgs has the zapret2 package but no NixOS module for it at all. The stock services.zapret targets the first version and refuses to configure nftables, so on NixOS you end up wiring systemd units and firewall rules by hand. I wanted to describe all of it declaratively, in one configuration.

v0.1 came out on 27 July 2026: the module, a preset library and checks on GitHub Actions. Claude and Codex agents wrote the code.

Available apart from active

The module separates what is available from what is switched on. Available presets are built into the Nix store from the configuration, and the active preset is a link in /var/lib/zapret2 that zapret2ctl switches. The nfqws2 service reads the active link, and firewall rules send the matching traffic to NFQUEUE.

The ports for the rules are derived from the presets themselves, so the rules cannot drift from the strategies. Bypass strategies go stale quickly and rebuilding the system for every attempt is painful, so zapret2ctl switch changes the strategy without a rebuild. There are four ready presets: YouTube, Discord and two general ones.

A check that does not lie

The awkward cases are part of the design. A running bypass service distorts a strategy test, so the wrapper stops it for the duration of the test. A VPN makes even an empty strategy look like it works, so the check refuses to run through a tunnel and does not accept it as evidence.

On 31 July two bugs were found and closed: reloading the firewall failed when there were no rules yet, and zapret2ctl status without root showed a store path and misreported the state. On 6 August a second family of strategies, narrowing to the WAN interface and list export for blockcheck2 were added; the quick check mode takes minutes instead of hours.

Where it stands

On 30 September 2026 CI runs three virtual machine checks: preset evaluation, the nftables path and the iptables path, with 14 steps in the shared scenario. CI also runs once a week, and the last run on 28 September is green.

A preset still depends on the ISP and can stop working when its DPI changes. An interface with automatic strategy discovery is planned for v0.2; for now discovery goes through blockcheck2 and zapret2ctl.

How it is built

Architecture
  • Available presets in the Nix store, the active preset as a link in /var/lib.
  • Firewall ports are derived from the presets.
Infrastructure
  • A flake with a NixOS module, the nfqws2 service in systemd, nftables or iptables.
  • CI on GitHub Actions with NixOS virtual machine checks, also weekly.
Fault tolerance
  • The service stops for the duration of a strategy test.
  • A check through a tunnel is refused.
  • A firewall reload does not fail without rules.
Decisions and assumptions
  • Switching strategy without a rebuild.
  • One set of preset data for both the strategy and the ports.
