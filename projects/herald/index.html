herald

A local MCP gateway between agent sessions and Telegram. It brings incoming messages and files into a session, sends prepared replies only along allowed routes, and through Watch lets me write to an already open session straight from the bot's private chat.

Why a separate gateway

Agent sessions need to receive working material and, less often, send something back. My material arrives as forwards from work chats, and replies go to management. If that runs through whatever channel is at hand, the agent is one mistake away from writing to the wrong person.

I wanted communication to be a small component with an explicit boundary, not an ability smeared across prompts. The first public release came out on 13 August 2026, and on 26 August herald became installable as a plugin for Claude Code and Codex. Claude and Codex sessions wrote the code; the boundary decisions and acceptance were mine.

Incoming: a temporary buffer, the archive in mnemo

Herald captures messages from the chosen Telegram topics together with reply context and files and puts them into a temporary local buffer. mnemo takes them from there and keeps them with their source, so herald does not become a second archive.

Since 14 September a message in the buffer counts as handled only when there is proof it was archived. The link to mnemo is still soft: captured material can be exported anywhere, and herald works on its own.

Outgoing: allowed routes only

In the other direction herald sends material the agent has prepared, but only to addresses and directories written in a configuration outside the repository. The public code names no real channel, and the decision whether to write at all stays with a person.

On 14 August a problem turned up in the instructions themselves: an agent preparing one message could add other projects' problems and questions about next steps. Fix b0bff52 made the subject of the request a hard boundary and limited questions to the first unknown dependency that blocks the next action; tests pin both wordings.

Later came copy-ready messages, file albums, named message batches, and packs of up to 100 files split into groups of 10. A send whose outcome is not confirmed is never retried automatically: it may have arrived.

The writing rules live in the configuration and are set per project. herald suggests the humanizer skill out of the box, and my rules add no-ai-slop to it. The link is soft: without the skills the message is still prepared and sent under the same rules.

Watch: light remote control

Watch appeared on 2 September, and since version 0.8.0 on 25 September it is on main. I write to the bot in a private chat with a profile tag, the message reaches an already open agent session, and the reply goes to a set topic. It is built from what herald already had: the inbox buffer, the list of allowed sources and the routes. Since 25 September attachments and voice messages reach the session too.

Watch does not start or wake sessions: only the session that took the profile and polls its queue answers, and a duty with no sign of life is released after 15 minutes. I deliberately kept it inside the gateway's boundaries: commands are accepted only from the owner in the configuration, and replies go out along the same routes.

Next, a thought out loud that I have not checked thoroughly. With one shared agent terminal running Watch, it could wake the others itself: Claude and Codex can resume a saved session and pass it a message, and Claude has its own tools for writing to other open chats. Then it would be enough to write to one terminal, and it would hand the task out to the working ones, even those without Watch. That would make a rather interesting remote control without complex infrastructure.

Where it stands

On 30 September 2026 herald is at version 0.8.0: 192 tests on main 8860f88, CI green. It carries communication in my work every day; in my work dailies from 18 to 28 September it is mentioned in 18 of 21. Together with mnemo and ephemeris it covers one path: a message arrives through herald, the material goes into the archive, and ephemeris keeps the course of the day. The links between them are soft, and each works on its own.

It runs locally and is meant for one operator, not a team deployment. The address list limits where material can go but does not judge whether it should be sent, and it does not protect a machine that is already under someone else's control.

How it is built

Architecture
  • An MCP server with 28 tools and three entry points: the gateway itself, capture, and the Watch monitor.
  • Three skills: drafts, sending and Watch.
Infrastructure
  • Python, MCP, httpx; SQLite for the buffer and delivery journals.
  • Runs locally; the repository ships a user systemd unit for capture, and one process polls per bot token.
  • Installed from the Claude Code and Codex marketplaces.
Fault tolerance
  • An unconfirmed send is never retried by itself.
  • Large file packs are split into groups of 10 and sent safely.
  • An abandoned Watch duty is released after 15 minutes.
  • A reply fallback is checked before sending.
Data and AI
  • Routes, directories and access are set by the operator in a configuration outside the repository.
  • The buffer is temporary; a message counts as handled only with proof of archiving.
  • Completed batch ledgers and unaddressed Watch messages have retention periods.
Decisions and assumptions
  • The allowed address list lives outside the code.
  • The buffer is temporary; storage is mnemo's job.
  • herald does not decide whether to write to a client.
  • Remote control stays inside the gateway's boundaries.
  • Soft links to mnemo, ephemeris and the no-ai-slop and humanizer skills.
