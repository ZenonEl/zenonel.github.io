Voice-over instead of subtitles

You can watch a video in an unfamiliar language if you accept subtitles or a separate browser extension. I wanted an app that plays a synchronised voice track over the original, on a computer and on Android.

I made the first commit on 10 March 2026. I started with the Gemini web chat and continued with Claude. On 11 March the translation request to a third-party service worked, with request signing and retries; on 14 March a second version arrived on the vot.js library with a cross-platform architecture; and on 21 March v1.0.0 came out. March brought 59 commits and nine releases.

How it works

The app wraps a WebView and injects a layer into the page that finds the video element with the vot.js library. A translation is requested for the detected video, and the returned track stays in step with the video: pause, seeking and speed are synchronised.

Injecting into a WebView instead of a browser extension gave one place where I control playback and one behaviour on every platform, at the cost of the trust an installed app asks for. Rust and Tauri 2 provide the shell, the injected layer is TypeScript, and part of the Android side is Kotlin. Versions 1.1 and 1.2 in April 2026 added Android features: opening shared links from other apps, picture in picture and background playback.

Verified and detected are different things

Detecting a video on a site does not mean the voice-over works there. The README separates the verified platforms, YouTube, VK and Vimeo, from those that are detected but untested: TikTok, Twitch, Twitter/X, Reddit, Rutube and others.

An early wording counted any detection as support and promised “55+ platforms”. On 30 September 2026 that was fixed at the top of the README too: it now also says what is verified and what is only detected.

Where it stands

The latest release is v1.2.0 from 25 April 2026, with builds on the releases page. There are no automated tests; the build process packages the app without a test step.

Translation goes through a third-party service via an integration made by reverse engineering, so it can stop working without any change on my side. The app sends that service the video's identity, which is a property of the feature itself. No active development is planned; if I come back, I will start by describing platform support afresh against the service's current behaviour.

How it is built

Architecture
  • A WebView with an injected video detection layer on vot.js.
  • The translated track is synchronised with the video: pause, seeking, speed.
Infrastructure
  • Rust and Tauri 2, TypeScript on Vite, Kotlin for Android.
  • Builds for Windows, Linux and Android come out through GitHub Actions on the releases page.
Fault tolerance
  • Requests to the translation service are signed and retried on failure.
  • HTTP and SOCKS5 proxies are supported.
Data and AI
  • The video's identity goes to a third-party translation service, which is a property of the feature.
  • The integration with the service was made by reverse engineering and can break.
Decisions and assumptions
  • A WebView instead of a browser extension.
  • An existing detection library instead of per-site rules of my own.
  • Verified kept apart from detected.
