CrabVoice

01Origin need

Watching a video in a language you do not speak is a solved problem only if you accept subtitles or a separate browser extension. I wanted a client that plays a synchronised voice track over the original.

02Who it is for

People who watch video in another language on desktop or Android and prefer an application over a browser extension.

03My role

Author. The client, the injection layer, and the synchronisation are mine. The translation itself is not.

04Architecture

The application wraps a WebView and injects a detection layer that recognises a video element on the page, using rules compatible with vot.js. A translation is requested for the detected video, and playback of the returned audio is kept aligned with the video timeline.

Rust and Tauri 2 provide the shell, and the injected layer is TypeScript.

05Design decisions

  1. WebView injection rather than a browser extension

    An extension is easier to ship and harder to keep across browsers and Android. A WebView gives one place to control playback and one behaviour to reason about, and it costs the trust an installed application asks for.

  2. Detection rules compatible with an existing project

    Reimplementing video detection for every site is an endless job. Following vot.js compatible rules meant the detection surface was already described.

  3. Say plainly which platforms were verified

    Detection covering a site is not the same as the flow working on it. The README separates verified platforms from detected but untested ones instead of publishing one large support number.

06A correction I had to make

The honest correction in this project was to the documentation rather than the code. An early framing counted every platform detection as support, which reads as a promise. Separating verified from detected made the project smaller on paper and accurate in use.

At the reviewed commit the README names three verified platforms: YouTube, VK and Vimeo. TikTok, Twitch, Twitter/X, Reddit, Rutube, Dailymotion, Bilibili, Kick and more are listed separately as detected and requiring testing.

07Tests, CI, releases

At reviewed commit 956e0d8 the repository contains no automated test files or test command, and the release workflow builds packages without a test step.

The latest published GitHub release is v1.2.0 from 25 April 2026. A published build shows that packaging completed for that release. It says nothing about behavioural coverage.

08Privacy boundary

The client sends video identity to a third party translation service, which is inherent to the feature rather than a side effect. The README documents that the integration is reverse engineered.

No security claim is made about this project. The translation path is outside my control.

09Limitations

  • The translation step depends on a third party service reached through a reverse engineered integration, so it can stop working without any change here.
  • Detected does not mean verified, and the README is the authority on which is which.
  • The project is earlier work. It is on this site for what it shows about handling parts of a system you do not own.

10Next steps

No active development is planned. If it resumes, the first task is restating platform support against the current behaviour of the translation service.

11Reproduction path

Release builds are published on the repository releases page, and the README is the place where verified platforms are listed.

The repository's source-build path is pnpm install followed by pnpm tauri build; it requires Node.js 20 or newer, stable Rust, pnpm and protobuf-compiler.
