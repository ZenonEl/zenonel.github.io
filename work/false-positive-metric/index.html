A product metric was counting refusals as success

A substring check reported 14 mentions out of 15 where a manual read found none. I replaced it with a calibrated claim verifier and made unsupported input stop before it could become a confident score.

01Safe context

A product asked language models whether they knew a brand, then turned the answers into a visible mention metric. The implementation looked for the brand name in the returned text.

That counted sentences such as 'I cannot verify this brand' as a mention. On one fresh run the report showed 14 out of 15 while a manual read found zero substantive mentions.

02Constraints

  • Unknown brands had to stop producing confident positive scores.
  • Known brands still needed to pass when the answer contained real, useful information.
  • The replacement had to fit the existing claim contract instead of changing every caller at once.

03What was mine

I traced the metric back to the substring rule, built the labelled cases, wrote the verification service, calibrated the rubric, and moved the refusal rule into the product path.

The uncomfortable part was treating the existing headline metric as untrustworthy until it survived a negative control.

04Team and agent boundary

Agents helped locate callers and exercise prompt variants. I read the captured answers, assigned the labels, and decided which mistakes mattered to the product metric.

The verifier is allowed to abstain. A forced answer would recreate the defect with more elaborate machinery.

05Alternatives I weighed

  1. Tighten the substring rule

    Cheap, but another list of negative phrases would only move the false positives around. The text can deny a claim in more ways than a rule can enumerate.

  2. Ask one model and trust its prose

    That keeps the original coupling between fluent text and a product score. Rejected for the same reason as the substring rule.

  3. Verify one claim against a strict rubric

    More expensive per answer and easier to inspect. It produces an explicit verdict, can abstain, and can be calibrated on known and unknown cases. This is what I built.

06Decision

Replace substring matching with a separate claim verifier. It receives the answer and known context, selects the matching rubric, and returns a structured verdict. Only a supported verdict may increase the metric.

The same rule now applies earlier too: if the input does not support a run, reject it before the graph is built instead of spending tokens on a result the product cannot stand behind.

07Implementation

  • A verification service behind the existing stable claim contract.
  • Separate rubric modes for known context and missing context.
  • Structured outcomes for a substantive match, denial, name-only text, a pivot, or an unsupported claim.
  • A refusal gate before graph execution and an explicit failure reason when generation is cut off.

The product's score names and the full labelled examples are omitted because together they would identify the system.

08How I verified it

I kept known and unknown cases separate. That matters because one skeptical rubric had removed false positives but also rejected ordinary, correct mentions of known brands.

  • The original failure replayed as zero real mentions against 14 reported by the old metric.
  • Known-case recall measured before and after the rubric change.
  • Unknown cases checked for substantive false positives, not mere name occurrence.
  • The stable claim contract left unchanged while the verifier changed behind it.

09Result

On the recorded control run, substantive mentions were zero where the previous metric had reported 14 of 15. In the later calibration, known-case recall rose from 64.3 percent to 100 percent while substantive false positives on the unknown set stayed at zero.

The product now carries the difference between no evidence and a positive claim instead of flattening both into a score.

10What this does not prove

The labelled sets were small. These figures show that the recorded failure class was closed; they do not establish model quality across brands, languages, or prompt styles.

A model verifier can still be wrong. The gain is a testable contract and an abstention path, not a guarantee that hallucinations are solved.

11What I would change now

I would keep expanding the labelled set with real boundary cases and report precision and recall by rubric mode, because a single aggregate can hide which side regressed.

I would also sample live abstentions for review. A refusal that is always safe and never useful is another broken metric, just in the opposite direction.
