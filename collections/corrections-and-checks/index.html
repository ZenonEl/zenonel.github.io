When a passing check misses the problem

Catalogue imports and product metrics can pass a check while failing the task. These cases explain the mismatch and what had to change.

01The check passed. The task did not.

In a catalogue import, checking for duplicate attributes was not enough. A size written as a point and the same size represented by a range were different strings, so both survived. The catalogue gained unwanted variants even though the duplicate check returned zero.

A product metric had a different problem: it counted the presence of a name in an answer, including an answer that refused to provide the requested information. The implementation could count the text correctly and still report the wrong outcome.

02What to read next

The catalogue case follows the failure through a database restore and a change in transformation order. The metric case explains what had to count as a result before there was any point comparing scores.

The cost-and-search case takes this further into evaluation: a cheaper proposal only helps if it still returns the material the task needs. The mnemo page covers another part of the same working process: keeping the original source available when a decision has to be revisited.
