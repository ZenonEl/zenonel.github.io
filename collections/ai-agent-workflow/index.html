Keeping context when the sessions are shorter than the project

Four tools and one habit. Material crosses a single boundary, is stored with its source, and reaches the next session as addresses rather than a retelling.

01Why this exists

Agent sessions are short and the project is long. Without something outside the session, each new one starts from a retelling of the previous one, and the further you go the less of the original material survives.

Nothing errors when this happens. The requirement drifts from what the client actually said, and by the time that matters the original message is three tools away.

02How the loop runs

  1. Material arrives from people and project channels and crosses one boundary, herald, into a local buffer.
  2. Mnemo imports it and stores it raw with its source, date, and attribution, and links it to requirements, decisions, and open questions.
  3. I work with agents against that material. Before the work starts, a kanon checklist records what the result will be accepted on. Agents inspect and implement. I choose the approach and check the result.
  4. Ephemeris records the state of the day and hands the next session addresses rather than a summary.
  5. When something needs to reach a person, herald sends it through an allowed route, and a person reads it before the client does.

The tools connect through links and published formats. Each one can be understood, and discarded, on its own.

03What agents do not decide

Agents read unfamiliar code faster than I do, hold more of a repository at once, and write a first version of a bounded change quickly.

They also produce nearly correct work, and such mistakes are expensive. So the loop keeps four things with me: what the requirement means, where the boundary goes, what counts as verified, and whether a result is allowed to leave the machine.

I do not read the code line by line. Generated work stays a draft until it has passed subagent review until LGTM, my manual and live checks, and a check against the requirements: what was asked for is done and nothing was lost. The cases show what this looks like in practice.

04What this does not prove

Four tools and a working habit are not a product. I am the only one using them, at work and on my own projects, and nothing here has been tested by a team under someone else's constraints.

The workflow reduces one specific loss, which is context evaporating between sessions. It does not make agent output correct, and it is not a security boundary.

05What is in this collection

  1. herald

    The boundary

    It is the one component allowed to move material between people and agents, and its allow-list is configuration rather than code.

  2. mnemo

    The memory

    It keeps the raw material with its source. On 4 September 2026, at management's request, the open questions of an e-commerce project went to management with a source address next to each; when the reply to the repeated list on 8 September showed one conclusion had been hasty, I corrected it from the original.

  3. ephemeris

    The handoff

    It carries the state of a work day across sessions as addresses, so a session does not start with a summary of a summary.

  4. kanon

    Acceptance

    Before the work starts it turns a task into a checklist with proof for each item, so the decision that something is done rests on the pasted result, not on a tick.

  5. The cost of an answer: cache, a narrow check and a search that failed its measurement

    The practice

    The commercial case where the same discipline paid: a measurement I could compare, and a rejected option kept in the record with the number that killed it.
