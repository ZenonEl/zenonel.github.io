Keeping context when the sessions are shorter than the project

Three public tools and one habit. Material crosses a single boundary, is stored with its source, and reaches the next session as addresses rather than a retelling.

01Why this exists

Agent sessions are short and the project is long. Without something outside the session, each new one starts from a retelling of the previous one, and the further you go the less of the original material survives.

The failure is quiet. Nothing errors. The requirement simply drifts from what the client actually said, and by the time that matters the original message is three tools away.

02How the loop runs

  1. Material arrives from people and project channels and crosses one boundary, herald, into a local buffer.
  2. Mnemo imports it and stores it raw with its source, date, and attribution, and links it to requirements, decisions, and open questions.
  3. I work with agents against that material. Agents inspect and implement. I choose the approach and check the result.
  4. Ephemeris records the state of the day and hands the next session addresses rather than a summary.
  5. When something needs to reach a person, herald sends it through an allowed route, and a person reads it before the client does.

The tools connect through links and published formats. Each one can be understood, and discarded, on its own.

03What agents do not decide

Agents read unfamiliar code faster than I do, hold more of a repository at once, and write a first version of a bounded change quickly. That is worth using.

They also produce work that is nearly correct, which is the expensive kind of wrong. So the loop keeps four things with me: what the requirement means, where the boundary goes, what counts as verified, and whether a result is allowed to leave the machine.

Generated code is a draft until I have read it, run it on the failing path, and understood how it behaves in the system around it.

04What this does not prove

Three repositories and a working habit are not a product. The tools are used by one person on his own projects, and nothing here has been tested by a team under someone else's constraints.

The workflow reduces one specific loss, which is context evaporating between sessions. It does not make agent output correct, and it is not a security boundary.

05What is in this collection

  1. herald

    The boundary

    It is the one component allowed to move material between people and agents, and its allow-list is configuration rather than code.

  2. mnemo

    The memory

    It keeps the raw material and its provenance, so a claim made three months later can be traced to the message that created it.

  3. ephemeris

    The handoff

    It carries the state of a work day across sessions as addresses, which is what stops each session from starting with a summary of a summary.

    The practice

    The commercial case where the same discipline paid: a measurement I could compare, and a rejected option kept in the record with the number that killed it.
