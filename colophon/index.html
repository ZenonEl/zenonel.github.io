Static HTML generated from a content model by a Python script with no dependencies. Of my own code the pages carry one script, which switches the theme and remembers which reading line you chose. The workflow diagram opens as a separate document with its own scripts and a text version next to it.

01What this site holds to

Every number on the site has a source in my private evidence files: a commit, a daily, a production log or a till report. Clients, companies and people are not named. What went wrong stays on the page next to what worked.

02How it is built

Every entry is a JSON file with an en and a ru block. A generator in the Python standard library reads them, checks them against the case and project schemas, and writes the whole site.

Stories have their own headings. The build checks that both languages contain the same sections in the same order, that the text is not empty, and that older fragment links still have a destination. All cases and projects are stories now; collections and service pages still use the original fixed section schema.

The newest rule also fails a required section that carries nothing but an owner-input marker. Structural presence was too easy to satisfy, and an empty section under a real heading reads as an answer.

03Sources, gaps, and omissions

The content model keeps sources and publication limits for editing and validation. Those internal labels are not shown as badges on the public pages.

When a number matters, the surrounding text says what was measured and where the boundary lies. A deliberate omission is explained in the sentence where it matters. A genuinely missing public fact remains an explicit TODO: owner input until it can be checked.

04What it does not use

  • No framework and no build toolchain. The generator has no dependencies outside the standard library.
  • No application framework and no site-wide runtime. Interactive diagrams run only inside their own same-origin documents.
  • No ads and no embeds.
  • One web font, served from this site, under an open licence, in two subsets.
  • One icon set, 26 files, vendored and inlined. No icon font.
  • The workflow diagram is an interactive map in its own document inside the page. A text version sits under it, so the diagram stays readable with styles or scripts off.

05Type, surface, and ink

The site follows the reader's system colour scheme: graphite at night and soft paper by day. If the browser reports no preference, graphite is the default. Geometry, type and hierarchy do not move between them, so the two palettes belong to one design.

Both palettes use three surfaces: the page, an inset panel, and a sheet on the panel. Text is near white on graphite and deep green-black on paper. Structure is carried by one-pixel hairlines in two weights: a quieter one inside a list and a firmer one where a section starts.

Text and headings are set in Onest, a grotesque drawn for Cyrillic and Latin alike, published under the SIL Open Font License. It is served from this site in a Latin and a Cyrillic subset, so Russian and English headings come from the same drawing. Metadata is set in the system monospace.

Softness comes from spacing and curvature, not from blur. There is no shadow anywhere in the stylesheet, and no decorative mark. Every line on a page separates, connects, or classifies something.

One botanical green accent, tuned separately for graphite and paper, appears only where it carries meaning: the current page, a hovered link, a gate on a diagram, and a section number. Every text colour is checked against WCAG 2.2 AA on all three surfaces in both palettes, and the lines that carry information clear the 3 to 1 ratio for non-text contrast.

Print uses a third palette, plain black on white. Navigation disappears and external link addresses are written out, so a printed CV or case remains readable without its screen chrome.

06The shape of a record

A deep record keeps the narrative in one reading column and a quiet navigation rail beside it. The rail contains only section links and relevant destinations; editorial status and source bookkeeping stay in the content model.

On a narrow screen the contents becomes a compact disclosure before the text. The reading order stays the same across layouts.

07Icons, and what they are not allowed to do

The site uses 26 Iconoir icons across navigation, project cards, fact strips, links, and diagrams. Only those 26 files are vendored into the repository under the MIT licence.

There is no icon font and no request. Each icon is inlined into the page at build time from one helper, so a concept is drawn the same way everywhere and adding one means vendoring a file rather than pasting markup.

An icon supports a label and never replaces one. A decorative instance is hidden from assistive technology in the markup, the word beside it stays, and the validator fails a link whose only content is an icon.

The licence ships with them at /assets/icons/LICENSE.txt.

08Checks

tools/build.py refuses to build content that breaks the schema. tools/validate.py checks the generated site: internal links and fragments, page metadata, language parity, the rendered section schema, dash usage and a short list of canned phrases, the single allowed script, external requests, the self hosted font declarations, and the publish boundary.

The privacy check is stored as digests of stems rather than as words, because a linter that spells out the identifiers it protects has already published them. Hashing stems rather than whole words is what catches an inflected form. A single word can be tested against the list with tools/validate.py --check-token.

HTML validation runs separately with html-validate, and the commands are in the README.
